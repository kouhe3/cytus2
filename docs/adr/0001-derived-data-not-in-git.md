# 派生数据不入库

游戏正文、实体记录、边关系、SQLite 索引、wiki 页面与 SPA 数据全部由 APK 经脚本生成，因此都不进 git；仓库只保留抽取脚本、手写 schema、人工覆盖层（如 `song_notes.json`）与前端源码。理由是：这些产物在游戏更新后会整体重算，入库只产生无意义 diff；同时仓库保持公开可分享，不成为游戏文本镜像。

## 考虑过的方案

- **结构层入库、正文层不入库**：仍会把可派生的实体与边版本化，更新时 diff 不可读，且带出一条「结构已过期、正文未过期」的错位风险。
- **全量入库**：仓库变成完整剧情库，公开仓库的版权与体积都不可接受。

## 后果

- clone 后必须解包 APK 并跑管线才能得到完整数据；schema 与脚本必须足以重建全部结构。
- 人工补充只能走覆盖层，不能直接改生成物，否则下次构建会被覆盖。
- 因为边也是派生的，「双向引用」永远是查询结果，不是需要同步维护的数据。
